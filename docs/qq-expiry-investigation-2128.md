# 2026-11-10 QQ播放失败核验（2.0.10 / 2128）

维护与新增功能：tiancaiProgramer。尚未发布GitHub，保留原版权及MIT许可。


> 后续2130实测补充：QQ网页登录未提供独立refresh_key/refresh_token时，仍可通过QQConnectLogin的音乐密钥交换续期。已真实验证两次换新密钥、重启保留及续期后音频读取。因此，缺少独立续期令牌不能单独用来判断QQ会话不可续期；2128当时的代码只尝试令牌路径确有遗漏。详见[2130续期记录](qq-renewal-2130.md)。

## 先核对规则

本地有账号编号和音乐Cookie，只说明曾保存凭据，不能证明服务端仍接受它。协议参考实现把is_valid（字段齐全）与is_expired（到期时间）分开，WEB登录需调用官方profile接口校验；续期需有官方返回且仍有效的refresh_key/refresh_token等信息。没有查到可普遍保证所有QQ/微信/网页登录都固定若干天有效的官方规则，不采用固定天数或未核实的设备数量作为判定。

## 实机只读检查

在应用内部使用现有会话，未退出、重登、主动续期或修改云端收藏；只导出错误码及布尔结果，未导出Cookie、音乐密钥、账号编号或续期令牌。

- 本地会话字段存在，但没有保存refresh_key/refresh_token。
- 官方profile校验HTTP200，业务code1000，校验不通过。
- 账号歌单查询仍返回HTTP200 / outer0 / rpc0及列表，不能把“能读歌单”当作完整认证有效的证明。
- 临时搜索探针返回rpc2001，未据此判定账号失效，亦未将未执行的vkey/CDN检查记为通过。此探针只用于保留当时证据。

因此，当前已证实存在服务端会话校验失败；现有数据无法凭空补出续期字段。需重新认证一次，再验证播放恢复，不能保证仅靠此前升级自动恢复。

## 本次修复

2127启动时会刷新资料，但profile返回明确鉴权失效后只被调用方忽略，未更新重新认证状态；播放接口可能成功返回空地址，从而没有命中RPC错误码恢复路径。

2128在profile鉴权失败时执行同账号恢复尝试，失败后显示重新认证提示；当各音质均无音源地址时再核对会话，明确失效就提示认证，资料校验正常则保留音源/权限错误，资料接口网络失败不当作掉线。恢复成功且凭据发生改变时重新解析歌曲，不用低档音质代替下载请求。

临时探针只存在于本地构建副本，交付的正常包移除探针。未对用户登录数据做过清除或修改来伪造过期。

## 认证后验证

2128正常原签名包已覆盖安装并移除临时探针。用户在官方页面完成QQ重新认证，试听后回复“已登陆、有声音”。当前系统媒体状态：PLAYING；错误：null。本次已捕获失效响应并确认认证后恢复，不等同于保证后续不会再次被平台撤销或要求认证。完整回归388项通过、5项联网检查默认跳过；此轮没有发布GitHub。

## 继续追查失效原因（源码审计）

本节是上述实机记录之后的源码与协议参考审计，没有再次安装、清除登录、主动刷新凭据或测量重登后的续期字段。

1. **能解释为何无法自动恢复。** 上次失效会话中续期字段为空；`recoverSession()` 只有在有 `refresh_key` 或 `refresh_token` 时才调用续期接口。其浏览器回退仅执行 `CookieManager.getCookie()`，只接受同账号且密钥变化的会话；读取旧 Cookie 本身不会进行网页登录或生成新密钥。
2. **网页登录采集存在范围限制。** `QqLoginActivity` 检测到账号和音乐密钥 Cookie 后即返回并销毁 WebView。`QqWebSession` 仅能采集指定名字的 Cookie，不能据此保证获取登录响应 JSON 中的续期字段。扫码交换目前会保留白名单中的续期字段，但前提仍是服务端实际返回。尚不能判定上次令牌缺失是旧版本漏存、该登录方式没有提供，还是网页响应采集不完整。
3. **没有完整的到期与提前续期机制。** 当前白名单未保存 `musickeyCreateTime`、`keyExpiresIn`、`needRefreshKeyIn`，也未依据这些时间安排提前续期。参考实现分别建模这些字段和续期凭据；现有资料无法回算此前密钥的真实到期时间。
4. **能解释为何界面仍像已登录。** 本地 `loggedIn` 只判断账号和密钥字段非空，头像另有缓存。歌单请求成功不证明受保护的播放鉴权有效。2128处理明确失效提示及空播放地址后的鉴权复核，但不等于已补齐登录凭据采集和提前续期。
5. **尚未确定服务端最初拒绝的触发原因。** 当时业务码1000可证明鉴权失败，但不足以区分自然过期、撤销授权或其他服务端原因；未记录到设备超限的专用错误，也没有证据证明是其他设备踢下线。不能宣称所有账号固定一天过期。

另检查了 jsososo/QQMusicApi 的旧 `/user/refresh`：代码尝试只携带音乐密钥调用 `QQConnectLogin.LoginServer/QQLogin`，但其历史 issue #186已有接口失效反馈。本轮未用真实账号调用该旧刷新路径，不把它视为经过验证的可用替代方案。

后续应优先验证官方登录实际返回的完整续期字段与有效期，再决定采集和提前续期方案；仅延长本地 Cookie 保存时间不能延长服务端凭据寿命。诊断只需保留字段是否存在、时间和错误码，不记录令牌值。
