# 网易云续期优化与回退（2.0.10 / 2131）

维护与新增功能：tiancaiProgramer。2026-11-10；手机正式版，随v2.0.10.2131发布。保留原版权和MIT许可。

## 修改范围

以已经安装且QQ续期实测通过的2130源码为基线，保留其全部QQ修复；Git HEAD仍是2127，不能用整体git reset回到HEAD代替此次回退。

- 网易云临时刷新失败不清Cookie、账号文件或已有登录；向调用方报告可重试异常，避免把原来的301传给资料页面而导致误退出。
- 刷新业务码200后重试原请求；业务301/401才按明确认证失败处理。其他业务错误、风险提示、网络超时和解析失败均保留凭据。
- 同一会话并发301共享一次刷新。原请求最多自动重试一次，连续失败冷却30秒；独立刷新请求有连接/发送/接收超时以及15秒总期限，且不会递归刷新自身。
- 认证签名只计算认证Cookie和一次刷新版本，忽略普通追踪Cookie变化；按请求URI读取匹配Cookie。重新初始化不会叠加重复拦截器。
- 退出与Cookie/账号文件写入串行，响应绑定会话代次，迟到Set-Cookie不得恢复已退出账号或覆盖新账号。账号实际切换时推进代次，手机/邮箱登录结果也核对原会话代次。
- 重试丢弃旧Cookie头，并使用内存中的原始业务参数重建加密正文，使EAPI里的认证头随Cookie更新。不持久化原始请求、不记录凭据；不重放登录、登出、注册和第三方接口。

## 验证记录

完整回归420项通过，5项显式联网测试默认跳过；新增17项专项覆盖网络、超时、格式错误、业务400/500、风险提示250、并发单次刷新、Cookie不变时的版本判断、重试上限、明确拒绝、取消、退出及换号迟到Set-Cookie、EAPI重建和追踪Cookie隔离。静态检查无错误或警告。过期错误使用虚构凭据和测试适配器模拟，不篡改真实账号凭据，也不把模拟过期写成实机自然过期。

真实手机保持原账号检查：资料读取200；原刷新接口400；资料再次读取200且仍为同一账号。另一次检查中原接口400、公开实现使用的EAPI兼容路径也为400，之后资料仍200且账号一致。因此本轮没有取得真实刷新200的证据，不能把有效的扫码登录说成刷新成功；EAPI兼容试验没有纳入产品。原来的错误处理可能把301之后的400直接清登录，新逻辑在此情形保留凭据，已由对应专项验证。

参考项目维护者也记录了二维码Cookie刷新400但其他功能正常的现象（历史记录，不能代替所有当前账号的实测）：https://github.com/Binaryify/NeteaseCloudMusicApi/issues/1421 。公开实现核对：https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/login_refresh.js 。临时探针只记录业务码和布尔结果，最终正常包移除探针。

本机工作目录 `work/netease-renewal-2131/rollback/` 保存：

- `baseline-manifest.json`：每个基线文件和压缩包SHA-256，以及当时Git HEAD与实际应用基线版本。

- `netease-2131-runtime.patch`：仅此次网易云运行时代码和专项测试的增量，反向应用检查通过；不包含QQ、版本号、署名或历史记录的撤销。
- `restore_netease_source.py` / `optimized-runtime-sha256.json`：带校验的源码回退工具，默认预览，显式--apply才执行。已在隔离副本验证预览、恢复、重复运行及拒绝后续修改四种情形，并核对QQ源码没有变化。
- 最终安装包校验信息由交付目录SHA256SUMS及verification.json记录。

另准备 **2132回退包**：使用2130业务源码及原签名，只提高Android内部版本号，便于在2131上覆盖回退，不必卸载或清除数据。该包保留QQ2130续期修复，仅撤回本次网易云优化。它是备用回退包，不作为正常升级发布。

### 回退操作

1. 保存出现问题时的操作、网络状态、界面提示与版本号；不要导出Cookie或密码。
2. 使用匹配架构的2132回退包覆盖安装，或者电脑执行 `adb install -r <回退APK绝对路径>`。不要卸载，不要清除应用数据。
3. 检查原账号、收藏、设置及播放是否保留，并记录回退结果。此轮不更改存储格式，不包含数据迁移。
4. 源码回退可先预览：`python3 restore_netease_source.py --repo /绝对路径/BuYu`，确认后加`--apply`。若目标文件已有后续修改，工具会停止，需人工合并。也可对照仅此次的增量补丁逐项撤销；不要整体回退到Git HEAD2127，以免丢失已验证的QQ修复。版本号、记录和账号数据不由源码回退工具改动。

2132已预留给回退包；后续正常构建从2133起递增，保证曾安装回退包的设备仍能直接覆盖升级。
