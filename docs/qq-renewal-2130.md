# QQ登录续期补齐（2.0.10 / 2130）

维护与新增功能：tiancaiProgramer。手机正式包候选，尚未发布GitHub；保留原版权和MIT许可。

## 实现

- 原生官方网页登录遇到精确的HTTPS `y.qq.com/portal/wx_redirect.html` 授权回调时，交回一次性授权码和登录类型；应用完成与官方页面一致的QQ或微信交换，防止回调页仅设置Cookie后丢弃响应JSON。不读取密码或验证码，不增加网页JavaScript桥。普通Cookie登录仍兼容，但不会宣称它具备完整续期令牌。
- 扫码和网页登录统一保存白名单中的 `openid/unionid/access_token/refresh_token/refresh_key/expired_in/expired_at` 及音乐密钥创建时间、有效期、建议刷新间隔；令牌只进原有Android设备绑定加密文件，不进入普通请求Cookie、公共头像缓存、日志或Git。
- 以服务端音乐密钥时间计算刷新时点，多日凭据预留最多24小时的续期余量，短期凭据提前量最多5分钟，并考虑建议刷新间隔。OAuth到期字段不当作音乐密钥寿命。没有有效期时，30分钟尝试间隔只是兼容策略，不能据此推断凭据寿命。
- 前台定时、回到前台、资料校验和RPC前均检查是否需要续期；Android冻结应用期间不能保证计时器运行，恢复时重新检查。并发共享一次续期，失败至少退避5分钟，普通网络错误不把有效会话改成已退出。明确鉴权失败仍显示重新认证提示。
- 新会话必须与原账号一致并通过官方资料校验，持久化成功后才替换。退出或切换账号阻止迟到写入。续期保留当前歌单列表；更新浏览器备用Cookie，避免备用路径又读回旧密钥。
- QQ会话没有独立refresh_key/refresh_token时，使用QQConnectLogin的音乐密钥交换；账号编号必须为数字。只有真实返回密钥并通过同账号资料校验后，才持久化成功记录。此方式已在本次用户会话得到成功响应；缺少独立refresh_token本身不是异常。
- 设置中的QQ续期项按真实支持的策略显示“支持自动续期”或“自动续期已验证”，可手动执行一次检查。不再把正常QQ密钥会话误标为需要补齐；同时兼容微信Cookie的wxopenid/wxunionid/wxrefresh_token别名。网易云已有独立的刷新拦截器，本次不更改。

## 自动验证

- 完整Flutter回归403项通过，5项显式联网测试默认跳过；相关46项回归通过，最终续期余量调整另通过15项专项。
- 新增15项测试覆盖官方QQ/微信回调交换与重启恢复、音乐有效期与OAuth有效期分离、请求前并发续期、定时续期、回到前台、网络失败退避、前后台鉴权合并、退出竞态、错账号拒绝和旧格式兼容；另验证长周期持续调度、网络恢复后的续期重试、微信字段别名及服务端明确拒绝后不自动轮询。
- 独立JVM执行14项官方回调解析检查：限制协议、主机、端口、路径和登录类型，拒绝伪造域名、用户信息、重复参数、畸形编码及空授权码。
- 相关静态分析无错误或警告；现有和新增的格式提示单独保留在本地分析记录。

## 实机验证与限制

2129用户重新认证后仍显示“补齐QQ登录续期”。安全探针核实：网页登录实际已保存openid、access_token、音乐密钥创建时间和有效期，但官方未提供独立refresh_key/refresh_token。随后QQConnectLogin/QQLogin返回outer0 / rpc0 / 非空音乐密钥，通过官方资料校验并成功保存；没有要求用户再次认证。由此纠正2129过于严格的状态判断。

2130实测连续两次续期均返回成功并取得与旧值不同的密钥；本次服务端音乐密钥有效期为259200秒（3天），不把样本视作所有账号统一规则。两次续期后都成功解析QQ歌曲并读取音频数据（HTTP206，读取32字节后停止；不是完整下载或扬声器试听）。第二次冷启动在续期前已经恢复“已验证”记录，证明续期状态已加密持久化并跨进程保留。最终无探针正常包已覆盖安装，已核对手机版本2.0.10（2130）且无启动崩溃；不再于每次启动强制刷新或读取测试歌曲。探针仅在本地构建副本中，不上传或分发；输出布尔状态、时间与错误码，不输出账号、授权码、令牌、Cookie或音频URL。

模拟回归不能代替真实服务验证，更不能保证授权被平台撤销后仍可免认证恢复。应用被冻结或完全停止期间无法持续续期；若凭据已经失效且官方不允许恢复，仍须重新认证。
